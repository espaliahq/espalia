description: Run system tests with auto-screenshots, then visually examine the captured UI.

## User Input

```text
$ARGUMENTS
```

## Instructions

Run one or more system tests with screenshot capture enabled, then visually examine every screenshot to verify the UI looks correct.

### Step 1: Determine which tests to run

- If `$ARGUMENTS` names a specific test file or path, use that.
- If `$ARGUMENTS` describes a feature or area (e.g., "participations", "login"), find the matching system test file(s) under `test/system/`.
- If `$ARGUMENTS` is empty, ask the user which system test(s) to run.

### Step 2: Run the tests with screenshots

Execute the test(s) with the `SCREENSHOTS` environment variable:

```bash
SCREENSHOTS=1 bin/rails test <test_file_or_path>
```

Do NOT pipe the output. If the tests fail, report the failures before examining screenshots.

### Step 3: Find the screenshots

List all PNG files under `tmp/screenshots/` that were generated by the test run. They follow the structure:

```
tmp/screenshots/{TestClassName}/{test_name}/{001_action_detail}.png
```

A namespaced test class dash-joins its namespace — `AssessmentCycles::EvidenceReportSystemTest`
writes to `tmp/screenshots/AssessmentCycles-EvidenceReportSystemTest/` — because
`actions/upload-artifact` rejects a colon anywhere in an artifact path.

### Step 4: Visually examine every screenshot

Read each PNG file using the Read tool. For each screenshot:

1. Describe what you see on the page (layout, content, visual state)
2. Note anything that looks broken, misaligned, or unexpected
3. Verify the UI makes sense for the action that triggered the screenshot (the filename tells you what happened)

### Step 5: Report findings

Provide a summary organized by test case:

- **Test name**: what the test covers
- **Screenshot count**: how many steps were captured
- **Visual assessment**: whether the UI flow looks correct
- **Issues found**: any visual problems, broken layouts, missing content, or unexpected states

If issues are found, suggest specific fixes with file paths.

### Step 6: Clean up

After reporting, ask the user if they want to keep or delete the screenshots from `tmp/screenshots/`.
